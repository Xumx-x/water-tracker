# 💧 喝了么 — 喝水追踪器

一个轻量、美观的每日饮水追踪工具。支持两种形态：

- **☁️ 云端共享版（推荐）**：`index.html` 部署到 **Vercel**，数据存 **Supabase** 云数据库，任何人通过链接即可注册使用，数据全局共享
- **💻 本地单机版**：`water-tracker.html` 双击即用，数据存浏览器 localStorage

> 📦 部署云端版请看 **[DEPLOY.md](DEPLOY.md)**（约 10 分钟完成）。

---

## ✨ 功能一览

### 🔐 用户系统（云端版）

- **注册/登录**：输入用户名 + 密码，首次输入自动创建账号
- **密码安全**：PBKDF2（10 万次迭代 + 随机盐）哈希存储，不存明文
- **会话缓存**：同设备下次打开自动登录
- **角色权限**：用户分普通用户 / 管理员（`profiles.role`）。管理员登录后导航栏出现「🛠 后台管理」入口，普通用户不可见；后台支持查看所有用户统计、重置密码、删除用户、全量备份/恢复
- **数据隔离**：每位用户只能看到自己的喝水数据；内部统一用用户 `id`（uuid 主键）关联，不再使用用户名作外键
- **防提权**：数据库已撤销匿名/普通角色对 `id`、`role` 两列的写权限

### 快速记录

- 四种预设容量一键记录：小杯 150ml / 标准杯 250ml / 大杯 400ml / 水瓶 500ml
- 自定义毫升数输入，回车即可添加
- 每条记录自动标注当前时间
- 卡片右上角「📅 补录历史」入口
- **🚰 自定义快速记录（云端版）**：设置页可自定义快捷按钮（图标/名称/容量），最多 8 个，每行 4 个自动换行；不自定义则使用默认 4 个

### 🏆 喝水量排行榜（云端版）

- 右侧栏常驻排行榜，展示所有用户的喝水量 Top 10
- **每日 / 每周 / 每月** 三档切换（每周按自然周、每月按自然月，展示统计区间）
- 前三名金/银/🥉 奖牌标识，当前用户高亮并带「我」标签
- 未进前十时底部显示自己的名次；记录/修改/删除后自动刷新

### 今日进度

- 环形进度图实时展示今日饮水量 / 目标 / 完成百分比
- 达成目标自动弹出庆祝提示 🎉
- 显示完成度、剩余量、记录次数

### 每日目标

- 默认 2000ml，支持 +/− 每次调整 100ml（位于「设置」页）
- 范围限制 500ml ~ 10000ml

### 今日记录管理

- 按时间倒序排列，显示杯子图标 + 时间 + 毫升数
- 内联编辑：点击 ✎ 直接修改毫升数，Enter 保存 / Esc 取消
- 单条删除、一键清空今日（带确认弹窗）

### 近 30 天趋势

- 历史记录页柱状图展示最近 30 天每日饮水量
- 今日柱条高亮，达标日显示绿色，鼠标悬停显示日期

### 📅 当月日历视图

- 颜色分级：灰色（无记录）/ 蓝色（有记录）/ 浅绿（过半）/ 深绿（达标）
- 月份切换、月度统计（合计/天数/日均/达标）
- 点击任意历史日期直接补录，今日高亮，未来日期不可点击

### 历史记录查看（独立页面）

- 按天折叠显示、分页浏览（10/20/50 条每页）
- 时间范围筛选：最近一周 / 一月 / 三月 / 全部 / 自定义（首次自定义自动预填最近 30 天）

### 历史日期补录

- 弹窗选择任意历史日期和时间补录
- 实时预览所选日期已有记录和合计
- 历史记录、日历中均可直接补录

### 数据管理

- **云端同步**：所有操作实时写入 Supabase，任何设备登录同一账号数据一致
- **📤 导出（用户级）**：下载当前用户数据为备份文件
- **📥 导入（用户级）**：从备份文件恢复，可用于旧版数据迁移
- **📤📥 全量导出/导入（管理员）**：备份/恢复所有用户数据，导入带预览确认

### 💬 喝友论坛（云端版）

- 导航「喝友论坛」独立页面，注册用户均可发帖（标题 + 内容）
- 支持对帖子 **点赞**（再次点击取消）与 **评论**，实时显示点赞数/评论数
- 顶部 **🔍 查询**：按标题 / 内容 / 作者关键词过滤；**🔄 刷新** 一键回到最新列表
- 自己的帖子可删除（点赞、评论级联删除）；帖子列表按发布时间倒序

### 🏆 荣誉墙（云端版）

- 导航「荣誉墙」独立页面，展示 **个人 4 类勋章** 累计次数 + **前 50 名用户勋章总榜**（日榜/周榜/月榜/达标 分列展示）
- **定时自动评选**（北京时间，pg_cron 驱动）：
  - 每日 01:00 生成昨日喝水量日榜 TOP3 → 上榜者「日榜勋章」+1
  - 每周一 01:00 生成上周周榜 TOP3 → 上榜者「周榜勋章」+1
  - 每月 1 号 01:00 生成上月月榜 TOP3 → 上榜者「月榜勋章」+1
  - 每日 01:30 统计昨日达标（饮水量 ≥ 每日目标）→ 达标者「达标勋章」+1
- **历史冻结**：榜单与勋章在生成时一次性写入快照，之后补录/修改旧数据不影响已生成的榜单与勋章次数；任务幂等（重复执行不重复计分）

## 🛠️ 技术实现（云端版）

### 数据模型（Supabase / PostgreSQL）

**profiles 表**（用户）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | uuid (PK) | 用户唯一标识，所有子表用 `user_id` 外键关联 |
| `username` | text (unique) | 用户名，登录标识 |
| `role` | text | `user`=普通用户 / `admin`=管理员，默认 `user` |
| `password_hash` | text | PBKDF2 密码哈希 |
| `goal` | integer | 每日饮水目标 |
| `custom_cups` | text | 自定义快速记录按钮（JSON） |
| `first_login` / `last_active` | timestamptz | 登录时间追踪 |

**water_records 表**（喝水记录）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | bigint (PK) | 自增主键 |
| `user_id` | uuid (FK) | 所属用户，级联删除 |
| `date` | date | 日期 YYYY-MM-DD |
| `time` | text | 时刻 HH:MM |
| `amount` | integer | 毫升数 |

**forum_posts / forum_likes / forum_comments 表**（喝友论坛）：

| 表 | 关键字段 | 说明 |
|------|------|------|
| `forum_posts` | user_id (FK) / title / content | 帖子，按创建时间倒序 |
| `forum_likes` | post_id (FK) / user_id (FK) | 点赞，`unique(post_id, user_id)` 防止重复点赞 |
| `forum_comments` | post_id (FK) / user_id (FK) / content | 评论，级联删除 |

> 注：因 Supabase anon 禁用聚合函数（PGRST123），点赞数 / 评论数由前端拉取明细后 JS 统计。

**honor_boards / honor_badges / honor_achieve 表**（荣誉墙）：

| 表 | 关键字段 | 说明 |
|------|------|------|
| `honor_boards` | board_type / period / rank / user_id / amount | 日/周/月 TOP3 榜单快照，`unique(board_type, period, user_id)` 保证幂等冻结 |
| `honor_badges` | user_id / badge_type / count | 勋章计数（daily/weekly/monthly/achieve），PK(user_id, badge_type) |
| `honor_achieve` | user_id / record_date / total / goal | 达标记录，`unique(user_id, record_date)` 防重复计分 |

- **定时任务**：pg_cron 4 个任务（北京时间 01:00 日榜/周榜/月榜、01:30 达标），均换算为 UTC 排程（`0 17 * * *` 等）；函数内部日期一律按 `Asia/Shanghai` 计算
- **冻结机制**：生成函数用 `INSERT ... ON CONFLICT DO NOTHING RETURNING`，只有榜单行/达标记录**新增成功**才发勋章 +1 → 历史数据补录不影响已生成结果，任务重跑也不会重复计分
- **写权限隔离**：三表 RLS 只开放 SELECT；生成函数已 `revoke` 掉 PUBLIC 执行权限，仅定时任务（postgres 角色）可写

### 架构要点

```
浏览器（index.html）
  ├─ 用户名+密码登录 → PBKDF2 校验 → 会话缓存 localStorage
  ├─ 内存数据缓存（同步渲染 UI）
  └─ 每次操作异步写 Supabase（增/删/改/查）
```

- **零后端**：Vercel 只托管静态文件，数据读写直接走 Supabase REST API（HTTPS）
- **内存缓存 + 异步同步**：UI 渲染沿用同步接口，数据落库为精确的增删改查
- **RLS 行级安全**：数据库开放读写，安全由应用层「用户名 + 密码」校验保证
  （适合亲友/团队内部使用；如需对公开放请改用 Supabase Auth）

### 技术栈

- 纯原生 HTML/CSS/JS，零框架
- Supabase JS SDK（CDN 引入，UMD 版）
- Web Crypto API（PBKDF2 密码哈希）
- 前端静态部署：Vercel

## 📋 使用流程（云端版）

1. 管理员按 **DEPLOY.md** 完成部署，把链接分享给大家
2. 用户打开链接 → 输入用户名 + 密码 → 自动注册/登录
3. 喝水后点击对应容量按钮记录，数据实时同步云端
4. 换设备登录同一账号，数据自动一致
5. 忘记密码 → 联系管理员在后台重置
